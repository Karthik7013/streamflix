## 2. Code Smells & Patterns

### 2.1 Duplicated Pagination Hook Logic (High)
Four hooks each independently implement identical patterns:
- `useState` for page, search, sorting, cursorRef, deleteTarget, dialog state
- `useDebounce` for search (300ms)
- `useQuery` with near-identical queryKey construction
- `goNext`/`goPrev`/`goToPage` with cursorRef management
- `useMemo` for total/totalPages extraction

**Files**: `hooks/use-admin-list.ts:22-106`, `hooks/use-admin-tags-page.ts:13-164`, `hooks/use-admin-reports.ts:22-137`, `hooks/use-admin-requests.ts:22-142`

**Impact**: Adding a feature requires touching 4 files. The only differences are the API module and entity-specific mutations.

### 2.2 Inconsistent Pagination Strategy (Medium)
- Admin hooks use cursor pagination (`cursorRef` + `gt(id, cursor)`)
- `use-admin-users.ts` uses offset pagination via Better Auth's `authClient.admin.listUsers({ query: { offset, limit } })`
- `Pagination` component branches on `useCursor` (presence of `goNext`/`goPrev`)

**Impact**: Inconsistent UX. Users list degrades at scale per AGENTS.md guidance.

### 2.3 Two Separate Pagination Engines (Medium)
- `lib/admin-list.ts::parseAdminListQuery` — cursor-based, used by admin services (movies-admin, tags, reports, requests)
- `services/paginated-list.ts::paginatedList` — offset-based, used by public services (movie search, tag movies)
Both reimplement sorting, filtering, and search-condition building independently.

### 2.4 Slug Generation Inconsistency (Medium)
Three different implementations:
- `lib/validation.ts::generateSlug()` (line 8) — thorough: NFD normalization, accent stripping, multi-hyphen collapse
- `entity-dialog.tsx::handleTmdbImport()` (line 132) — `title.toLowerCase().replace(/[^a-z0-9]+/g, "-").replace(/^-+|-+$/g, "")` — no accent normalization
- `services/tags.ts::createTag()` (line 82) and `updateTag()` (line 92) — `name.toLowerCase().replace(/\s+/g, "-").replace(/[^a-z0-9-]/g, "")`

### 2.5 Cache Invalidation Scattered in Route Handlers (Medium)
`invalidateCache("movies-list")`, `invalidateCache("home")`, etc. called inside API route handlers.

**Files**: `api/admin/movies/route.ts:32-33`, `api/admin/movies/[id]/route.ts:33-35`, `api/admin/tags/route.ts:26-27`, `api/admin/featured/route.ts:25`, etc.

**Impact**: Services called from CLI scripts or cron jobs won't invalidate cache. Logic duplicated across 8+ route files.

### 2.6 `invalidateCache` Sequential Pattern Scanning (Low-Med)
`lib/cache.ts:90-111` — iterates patterns sequentially, calling `findKeys` (SCAN) one at a time. Could parallelize with `Promise.all`.

### 2.7 Redundant Code in Upload Routes (Low)
`api/upload/cover/route.ts:5-22` and `api/upload/avatar/route.ts:5-22` — identical `EXTENSION_MAP`, `extFromContentType`, `requireEnv`.

### 2.8 `HomeContent` Stubbed Retry Handlers (Low)
`app/(main)/home/home-content.tsx:18-19` passes `loading={false}`, `isError={false}`, `retry={() => {}}` as hardcoded props. Server component handles all data fetching; client error UI is dead code.

## 3. Bugs & Defects

### 3.1 Cursor Pagination Broken for Tags, Reports, Requests (High — Bug)

**Root cause**: `lib/admin-list.ts:64` hardcodes cursor on `config.sortableColumns["id"]`:
```ts
const cursorWhere = cursor ? gt(config.sortableColumns["id"] as AnyColumn, cursor) : undefined;
```

**Affected configs** (missing `id` from `sortableColumns`):
- `services/tags.ts:23-33` — `sortableColumns: { name, createdAt }` — no `id`
- `services/reports.ts:6-17` — `sortableColumns: { createdAt, updatedAt, status }` — no `id`
- `services/requests.ts:6-19` — `sortableColumns: { title, status, createdAt, updatedAt }` — no `id`

**Trigger path**: `goNext()` in hooks sets `cursorRef.current = items[items.length-1].id`, then subsequent query sends `cursor` param. Server receives cursor, `parseAdminListQuery` evaluates `gt(undefined as AnyColumn, cursor)` → invalid SQL.

**Note**: `moviesListConfig` in `services/config.ts` DOES include `id`, so movies admin pagination works.

**Impact**: Paging to page 2+ on admin Tags, Reports, and Requests pages throws a SQL error.

### 3.2 `MostFavoritedMovie` Type Field Name Mismatch (Medium — Bug)

- `types/index.ts:117-123` — interface has `favCount`
- `lib/api/admin.ts:12-18` — interface has `favoriteCount`
- `services/stats.ts:16` — returns `favCount`

`adminApi.mostFavorited()` returns `{ data: MostFavoritedMovie[] }` (from `admin.ts` type), but the actual response has `favCount`. The `MostFavorited` component (`app/admin/most-favorited.tsx:12`) expects `m.favCount`. The admin API client type lies — it says `favoriteCount` but data has `favCount`.

**Impact**: TypeScript compiles but the typed client is incorrect. If someone uses `adminApi.mostFavorited()` and accesses `.favoriteCount`, they get `undefined` at runtime.

### 3.3 Error Code Case Mismatch — 404s Never Show `MovieNotFound` (Medium — Bug)

The API returns error code as `"NOT_FOUND"` (uppercase), but two components check for lowercase `"not-found"`:
- `app/(main)/movies/[slug]/movie-detail-client.tsx:67` — `error.code === "not-found"`
- `app/(main)/watch/[slug]/watch-content.tsx:37` — `error.code === "not-found"`

`ApiError.code` is set from `parseErrorBody` which reads `parsed.error.code` directly from the API response (`NOT_FOUND`).

**Impact**: Navigating to a non-existent movie on the detail or watch page shows the generic "temporarily unavailable" message instead of the `MovieNotFound` component.

### 3.4 `use-video-engine.ts` Over-Recomputed useMemo (Low-Med)
127-156 — 23-item dependency array. Any progress tick (every 250ms on time update) recomputes the entire object, invalidating all child `useEffect` deps in `useKeyboardShortcuts`, `usePlayerUI`, etc.

### 3.5 `api.ts` Headers Type Cast (Low)
`lib/api/client.ts:27` — `options?.headers as Record<string, string>` loses type safety if `Headers` object or array is passed.

## 4. Maintainability Concerns

### 4.1 `use-admin-tags-page.ts` Reimplements `useAdminList` (Medium)
164 lines. The pagination/search/sorting logic duplicates `use-admin-list.ts` entirely. CRUD mutations are inlined and could be separated.

### 4.2 `FeaturedPage` Tight Coupling to Hook Return (Low-Med)
`app/admin/featured-page.tsx` accepts `UseAdminFeaturedReturn<T>` — the entire hook return object. Presentation component is coupled to hook internals.

### 4.3 `chat/route.ts` — Inline AI Tool Definitions (Medium)
198 lines. 5 tools defined inline as `Record<string, any>` with `eslint-disable`. No test independence.

### 4.4 `ai-elements/prompt-input.tsx` — 1496 Lines (High)
40+ exports. AGENTS.md says split >300 lines, but this is vendored component-library style. Navigation difficulty only concern.

### 4.5 Error Shape Inconsistency (Low-Med)
Services return `{ error: { message, code } }` but `validateBody` adds `details` to the error shape. Route handlers inconsistently access `result.error.code` vs spreading `result` directly.

### 4.6 `use-player-ui.ts` Confusing `setIdle` (Low)
`setIdle` uses `setActiveAt(v ? 0 : Date.now())` — setting idle to true sets activeAt to 0 (epoch), making idle always true. Non-obvious but functional.

### 4.7 `useUpload` Uses XMLHttpRequest (Low)
`hooks/use-upload.ts:45-78` — uses `XMLHttpRequest` for upload progress, while the rest of the codebase uses `fetch`. Modern `fetch` with `ReadableStream` can achieve the same with less code.

## 5. Strengths (Things Done Well)

1. **Consistent auth wrapper pattern** — `withAuth`/`withAdminAuth`/`withPublic`/`withOptionalAuth` in `lib/with-auth.ts` eliminates try/catch boilerplate
2. **Typed API client** — `adminApi`, `moviesApi`, `tagsApi`, etc. in `lib/api/` — zero raw `apiFetch` in page files
3. **Centralized cache invalidation** — `invalidateCache` with named scopes (`movies-list`, `movie-detail`, `home`, `tags`, etc.)
4. **Fail-fast env loading** — `requireEnv` pattern in `upload-utils.ts`, `auth.ts`, `tmdb.ts`
5. **RAG/embedding batching** — `nvidiaEmbed` batches 16 vectors per API call
6. **Upload pipeline** — `uploadToIA` handles S3 signing, file validation, error handling
7. **streamflix-player hook extraction** — 8 focused hooks instead of one massive component
